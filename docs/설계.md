# 설계

클래스를 **만드는 순서대로** 적었다. 각 클래스는 `src/클래스명.java` 파일 하나다.
슬라이드에 적힌 내용은 [슬라이드], 팀이 정할 내용은 [결정 #번호](`docs/결정사항.md`)로 표시한다.

---

## 1단계. ChatMessage

메시지 한 개(메모지 한 장).

| 구분 | 내용 |
|---|---|
| 필드 | `role` (system / user / assistant), `content` [슬라이드] |
| 생성자 | `ChatMessage(role, content)` |
| 메서드 | getter 2개, `toString()` → `"ROLE: content"` 형식 |

구현 방법
- role은 system / user / assistant 세 가지만 쓴다. 다른 값이 오면 어떻게 할지는 구현 담당이 정하고 PR에 적는다.
- `toString()` 형식은 `toPromptText`에서 그대로 쓰므로 여기서 한 번만 정한다. ROLE은 대문자.

---

## 2단계. ConversationBuffer

메시지를 순서대로 쌓는 배열(파일철).

| 구분 | 내용 |
|---|---|
| 필드 | `ChatMessage[] items`, `int size` [슬라이드] |
| 생성자 | `ConversationBuffer(int initialCapacity)` — 초기 용량 [결정 #5] |
| `add(ChatMessage)` | 끝에 추가. 꽉 차면 2배 확장 [슬라이드] |
| `toPromptText(int lastK)` | 최근 K개를 `ROLE: content` 줄로 합쳐 반환 [슬라이드] |
| `clear()` | 이력 비우기 [슬라이드, 선택] |
| 기타 | `size()` 조회 |

구현 방법
- `add`: `size == items.length`이면 길이 2배 새 배열을 만들고 for문으로 0 ~ size-1을 복사한 뒤 `items`를 새 배열로 바꾼다. 그다음 `items[size]`에 넣고 `size++`.
- 초기 용량이 0이면 2배 해도 0이므로 최소 1을 보장한다.
- `toPromptText`: 시작 위치 = `size - min(lastK, size)`. 시작 위치부터 `size - 1`까지 `toString()`을 줄바꿈으로 잇는다. lastK ≤ 0이면 빈 문자열.
- `clear`: `size = 0`. 배열 칸을 null로 지울지는 선택.

## 2단계. LLMClient (스텁)

진짜 AI 대신 규칙대로 문장을 만드는 가짜 응답기. ConversationBuffer와 동시에 만들 수 있다.

| 구분 | 내용 |
|---|---|
| 필드 | `apiKey`, `model`, `temperature`, `maxTokens` [슬라이드] |
| 생성자 | `LLMClient(apiKey, model, temperature, maxTokens)` [슬라이드 41] |
| `generate(String prompt)` | 규칙 기반 가짜 응답 반환 [슬라이드] |

구현 방법
- 응답 규칙 [결정 #9]: 같은 프롬프트면 항상 같은 응답. 응답은 **여러 줄**(PlannerBot 확인용). 예: 모델명, 프롬프트 글자 수, 프롬프트 마지막 줄 요약을 각각 한 줄씩.
- `Random` 사용 금지 (출력이 매번 바뀌면 테스트 불가).
- maxTokens는 응답 글자 수 상한으로 쓰고, temperature는 저장만 한다 [결정 #10].
- prompt가 null이면 빈 문자열로 취급.

## 3단계. ChatBot (부모)

정해진 5단계 순서로 답하는 기본 상담원. 1·2단계 클래스를 모두 사용한다.

| 구분 | 내용 |
|---|---|
| 필드 | `name`, `systemPrompt`, `ConversationBuffer history`, `LLMClient client`, `int keepLastK` [슬라이드] |
| 생성자 | `ChatBot(name, systemPrompt, client, keepLastK)` [슬라이드 41] — 안에서 빈 history 생성 |
| `reply(userInput)` | 5단계 고정 흐름 [슬라이드] |
| `buildPrompt(userInput)` | 프롬프트 조립. 자식이 오버라이드 가능 [슬라이드] |
| `postProcess(raw)` | 응답 후처리. 자식이 오버라이드 가능 [슬라이드] |
| `reset()` | 이력 초기화, systemPrompt 유지 [슬라이드] |

`reply()` 5단계 [슬라이드]

| 순서 | 동작 |
|---|---|
| ① | history에 user 메시지 추가 |
| ② | `buildPrompt(userInput)`로 프롬프트 조립 (최근 keepLastK개 포함) |
| ③ | `client.generate(prompt)` 호출 |
| ④ | `postProcess(raw)`로 후처리 |
| ⑤ | 결과를 assistant 메시지로 history에 추가하고 반환 |

구현 방법
- `reply`는 `final`로 고려 (자식이 순서를 못 바꾸게).
- `buildPrompt` 기본형: `SYSTEM: systemPrompt` 한 줄 + `history.toPromptText(keepLastK)`.
- 현재 입력이 ①에서 이미 history에 들어가므로, buildPrompt에서 userInput을 다시 붙이지 않는다 [결정 #2].
- systemPrompt는 필드로만 두고 history에 넣지 않는다 → reset은 `history.clear()`만 하면 된다 [결정 #1].
- `postProcess` 기본형: `trim()` 또는 그대로 반환 [결정 #11].
- 필드는 private. 자식이 써야 하는 것은 protected 또는 getter.
- 디버그용: 마지막으로 만든 프롬프트를 저장해 두고 출력할 수 있게 한다 (FaqBot·KoreanBot 확인용).

## 4단계. 자식 챗봇 4개 (병렬 가능)

모두 `extends ChatBot`. 공통 규칙: 오버라이드할 때 `super`의 결과를 받아 덧붙인다.

### FaqBot + FaqEntry

| 구분 | 내용 |
|---|---|
| FaqEntry 필드 | `keyword`, `answer` [결정 #7] |
| FaqBot 추가 필드 | `FaqEntry[] kb`, `int kbSize` [슬라이드] |
| 생성자 | `FaqBot(name, systemPrompt, client, keepLastK, kb초기용량)` [슬라이드 41, 결정 #6] |
| `addFaq(keyword, answer)` | kb에 추가, 꽉 차면 2배 확장 |
| 오버라이드 | `buildPrompt` [슬라이드] |

구현 방법
- 입력에 keyword가 포함(`contains`)된 항목을 모두 찾는다 [결정 #8].
- 프롬프트 = `[관련 FAQ]` 블록(매칭된 Q/A) + `super.buildPrompt(userInput)`. "관련 FAQ 우선, 그다음 일반 답변" [슬라이드].
- 매칭이 없으면 FAQ 블록 없이 부모 결과만.

### TutorBot

| 구분 | 내용 |
|---|---|
| 추가 필드 | `String[] examples`, `int exSize` [슬라이드] |
| 생성자 | `TutorBot(name, systemPrompt, client, keepLastK, 예제초기용량)` [슬라이드 41, 결정 #6] |
| `addExample(String)` | examples에 추가, 꽉 차면 2배 확장 |
| 오버라이드 | `buildPrompt` [슬라이드] |

구현 방법
- 프롬프트 = `[예제]` 블록(예제 전부 나열) + `"단계별로 간결히 설명하라"` 지시 + `super.buildPrompt(userInput)` [슬라이드].

### PlannerBot

| 구분 | 내용 |
|---|---|
| 추가 필드 | 없음 |
| 생성자 | `PlannerBot(name, systemPrompt, client, keepLastK)` [슬라이드 41] |
| 오버라이드 | `postProcess` [슬라이드] |

구현 방법
- `super.postProcess(raw)` 결과를 줄 단위로 나눠, 빈 줄을 빼고 각 줄 앞에 `- [ ] `를 붙여 다시 합친다 [슬라이드].
- 줄 나누기에 `split` 사용 가능 여부는 [결정 #13, 보류].

### KoreanBot

| 구분 | 내용 |
|---|---|
| 추가 필드 | 없음 |
| 생성자 | `KoreanBot(name, systemPrompt, client, keepLastK)` (슬라이드 41에 예시 없음, 다른 봇과 같은 형태로 맞춤) |
| 오버라이드 | `buildPrompt` [슬라이드] |

구현 방법
- 프롬프트 = `super.buildPrompt(userInput)` + `"모든 답변은 한국어로 작성"` 지시를 항상 포함 [슬라이드].
- 스텁은 실제 한국어를 만들지 못하므로, 생성된 프롬프트에 지시문이 들어 있는지로 확인한다 [결정 #12].

## 5단계. Main

슬라이드 41 데모를 그대로 실행하는 진입점. 주석 처리된 `addFaq`, `addExample`도 실제로 호출해 FAQ·예제가 프롬프트에 붙는지 보여 준다. KoreanBot 데모 한 줄 추가.
